# QuickPeek 0.1.15 性能和回归测试

版本提交 `53cc20a`。测试在同一台 Windows 11 build 26300、i5-13600KF、RTX 4060 Ti、约 32 GB 内存的机器上串行执行。打包程序 SHA-256 为 `d90ff95f63168a3e7be1f2ece9925d380f17dd23ae45aa7c63d6e3c1ec5f1a96`。

## 资源管理器空格预览

从发出空格键开始，到正确文件的窗口处于前台且屏幕像素匹配为止。PNG 校验中心颜色，文本和代码校验两行不同位置的字形。每次再按空格关闭，检查窗口已关闭、焦点已回到同一个 Explorer 窗口。P95 按最近秩计算。

| 场景 | 成功次数 | 中位数 / P95 / 最慢（ms） |
|---|---:|---:|
| 0.1.14，两张 PNG | 30/30 | 298 / 587 / 594 |
| 0.1.15，两张 PNG | 30/30 | 149 / 186 / 191 |
| 0.1.15，PNG、TXT、PS1 混合 | 100/100 | 142 / 160 / 182 |

混合序列按 PNG、TXT、PNG、PS1 轮换，使用 4 个文件，共 100 次。相同文件重复使用时系统磁盘缓存可能命中。新版 130 次均验证了关闭及焦点返回，旧版基线只记录打开。复测命令为 `pwsh -File scripts/test-explorer-latency.ps1`，添加 `-ImagesOnly -Rounds 30` 可测纯图片序列。

诊断构建中，16 次请求从进入选择线程到取得当前选择，中位数为 20 ms；管道到达渲染进程为 1 ms；从收到路径到进入窗口定位为 52 ms。原实现每次消耗一个预热进程，连续打开会等待下一个进程启动。原窗口激活调用还会模拟 Alt，部分情况下需要延迟恢复焦点。新版复用 GPUI 运行时，每次创建独立的预览窗口，并在窗口创建期间开始解码图片。打开另一个文件时，已置顶预览保持独立。没有预览活动后约 30 秒回收渲染工作进程，恢复为轻量待命状态。

## 回归范围

21 项 Rust 测试、Clippy 和不启用 GPUI 功能的构建检查通过。实机验证了图钉、独立置顶窗口、修改同路径图片后重新读取、标题栏拖动和窗口控制、文本滚动条、图片滚轮缩放、重命名文件时输入空格、Markdown 渲染与查找、PDF 选区和缩放、视频控制以及压缩包层级和成员预览。未覆盖其他硬件、系统冷启动、网络盘或长期运行。

早期 PDF 测试遇到 Windows 剪贴板恢复错误，无法确认原内容已恢复。最终 PDF 检查直接验证文字选区，不写系统剪贴板。
