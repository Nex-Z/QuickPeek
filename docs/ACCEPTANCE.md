# 首版验收记录

日期：2026-09-22。环境：本机 Windows 11 x64，Rust 1.98.1，windows-reactor 0.100.0。

## 0.1.6 阅读布局与大文件性能（2026-09-26）

- 图片仅保留默认等比适配，移除三种模式按钮；滚轮滚动、Ctrl+滚轮缩放回归通过。
- Excel 使用合理列宽、固定行高、横向滚动、冻结表头及行号；长单元格省略显示，选中后查看完整值。CSV 表头紧贴滚动容器顶部，滚动后顶部偏差实测为 0。
- HTML / Markdown 源码、JSON 和常见代码统一使用离线语法高亮；大文本仅挂载可见分块，限制单块着色工作量。
- 文件读取与同目录导航列表分离；图片保留原编码直接加载，WebP 才转换。表格先提供首屏，翻页时加载完整行数据。文本上限提高至 16 MiB。
- 本机独立进程、新 WebView2 配置实测：5–10 MB 日志、JS、JSON、CSV 及 10.9 MB XLSX 首屏约 0.9–1.3 秒；检查完整文本及表格最后一行，未以截断数据换取速度。5–10 MB Markdown / HTML 实测约 0.9–1.1 秒，按完整区块分页，避免一次布局全部节点。性能取决于设备、文档结构及系统缓存，不是所有文件的固定耗时保证。
- Excel 仍以保存的单元格值为主，不复刻完整工作簿排版。干净系统与多屏混合 DPI 的完整验收仍待补充。
- 复现：`py scripts/make-performance-fixtures.py`、`node scripts/test-performance.cjs`；原始测量保存在 `docs/evidence/performance.json`。

## 0.1.5 文件预览修复（2026-09-26）

- 修复旧预览进程存在时托盘直接忽略空格的问题。原生测试保留第一个窗口，再从 Explorer 打开第二个文件；两窗口均存在，新窗口获得前台且未设置 TOPMOST。
- 新进程获准激活前台；跨屏 DPI 改变尺寸后按最终物理尺寸重新居中。八类格式的居中、置顶切换、标题栏对齐、键盘导航及重命名输入回归通过。
- 用户 PNG（1448×1086）和 WebP（1027×1948）通过 Rust 解码后以图像数据加载，避免文件 URI / 系统格式支持差异。默认按窗口宽高等比适配，提供适应宽度、原始大小。真实滚轮缩放/滚动及完整图片显示已验证。
- 日志、JSON 使用 WebView2 分块连续文本，保留缩进和跨行选择。JSON 在 Rust 中格式化，保留大整数及键顺序，提供原文切换和格式化按钮。加载新文件重置阅读模式。
- HTML、Markdown 默认渲染，支持源码切换；Markdown 保留标题级别、嵌套列表、代码、表格和同目录图片。隔离框架不执行被预览文档的脚本，不加载远程资源。
- CSV / TSV 支持引号字段与字段内换行，默认表格、分页和源码切换。Excel 支持工作表选择和单元格值分页。用户 XLSX 验证为 467 行、52 列，第二页从第 101 行开始。
- WAV 音频及 MP4 视频实际验证打开即播放、时间推进、暂停/继续。其他媒体格式仍取决于系统解码器。
- 13 项 Rust 测试、严格 Clippy、release 构建通过。`test-native.ps1`、`test-regressions.ps1`、`test-reader.cjs`、`test-reading.ps1` 分别覆盖窗口/键盘、用户图片与媒体/重复空格、嵌入式阅读器、图片/PDF 鼠标交互。
- 本机实测后台读取与准备：140,890 字节日志约 2 ms，JSON 约 1 ms，XLSX 约 13 ms。独立启动进程及新 WebView2 配置后，六种阅读页就绪约 0.8–1.0 秒；并非跨设备性能保证。阅读器测试通过真实应用的本地 DevTools 端口检查分页、源码切换、连续选择和原生 Ctrl+F 焦点。
- Excel 显示保存的单元格值，不重新计算公式、不复刻图表/合并单元格/完整样式；每工作表最多 20,000 行、256 列，文本最多前 2 MiB。尚未做干净系统的完整验证。

## 0.1.4 阅读交互（2026-09-26）

- PDF 从单页栅格图片改为 WinUI WebView2 阅读器；本机真实鼠标拖选并复制得到 `QuickPeek - Page 1`，普通滚轮滚动到第 2 页，Ctrl+滚轮放大和缩小正常。
- 图片始终处于滚动容器中；600×2400 长图可上下滚动，Ctrl+滚轮缩放后可以横向滚动，缩回 100% 后仍可继续阅读。
- 普通文本改为连续的可选择文本控件；240 行样例无需翻页，跨行选择与滚轮滚动通过。Markdown 渲染不再按 160 行拆断，源码模式支持连续选择。
- PDF 保留 Space、方向键、Enter、Ctrl+F 等阅读器输入；Esc 关闭预览。其他格式保留原有快捷键，高亮代码 / JSON 仍按 160 行分页。
- `cargo test` 8 项通过，严格 Clippy 与 release 构建通过；八类格式的标题栏、置顶、搜索和视频操作原生回归通过。新增 `scripts/test-reading.ps1`，使用 SendInput 注入实际鼠标移动与拖动，避免只改变光标坐标造成 WebView2 拖选测试误报。
- 阅读测试截图见 `docs/evidence/reading-pdf-selection.png`、`reading-pdf-zoom.png`、`reading-pdf.png`；已目视确认真实文字选择、放大后的页面和第 2 页。
- PDF 依赖本机 WebView2 Runtime；扫描 PDF 无文字层时不支持直接选择文字。未新增 OCR，未做干净系统和多屏混合 DPI 的完整验收。

## 实现与验收边界

Windows 11 活动资源管理器标签页通过 shell browser 子窗口筛选；不同 Windows 构建仍需更广兼容性验证。
首版为便携预览功能版本，不是性能最终优化版本；未给出冷启动 / 峰值内存 / 长时间稳定性承诺。
尚未完整验证：干净虚拟机、混合 DPI 多屏、HDR、所有图片和视频编解码器、损坏媒体压力测试。
PDF 使用 WebView2 阅读器；Markdown 使用隔离 HTML 渲染。第三方插件执行宿主尚未实现，只有版本化接口预留。

## 复现

```powershell
cargo test
cargo clippy --all-targets -- -D warnings
cargo build --release --locked
powershell -ExecutionPolicy Bypass -File scripts/test-native.ps1
powershell -ExecutionPolicy Bypass -File scripts/package.ps1 -SkipBuild
```

测试使用仓库内的专用样本，不读取或改写用户业务文件。媒体样本通过 `ffmpeg` 测试信号生成，PDF 通过 `scripts/make-fixtures.py` 生成。
